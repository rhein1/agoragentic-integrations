A three-minute walkthrough

Three minutes is a suggested presentation length, not a verified hackathon rule. Use the four preset buttons above the workbench.

0:00–0:25 · Explain the job

“Research this supplier. Spend only when fresher or deeper information is needed.” Point at the goal, budget and mode label.

0:25–0:50 · Free answer

Click 1 · Free answer. The public snapshot is adequate for an overview, so the agent selects zero demo units. It does not spend just because it can.

0:50–1:20 · Useful purchase

Click 2 · Useful purchase. The old snapshot is too stale. The current registry is the lowest-cost adequate choice at two units. Point to the brief. State that the purchase is simulated.

1:20–2:00 · Malicious bargain

Click 3 · Inject an attack. The one-unit source carries an instruction to override approval. It is refused; the agent still selects the legitimate current registry. These are controlled fixtures, not a universal prompt-injection test.

2:00–2:25 · Owner stays in control

Click 4 · Revoke permission. The run stops. Also try a detailed assessment with budget four: an inadequate cheap source must not be bought.

2:25–3:00 · Inspect the evidence

Click Export evidence. Explain which mode ran. “Risk Fork separates untrusted work; the clean side controls permission; the Dynamic runner is the next separately qualified step.”

Run the actual reference demo

Use Node 22 or later. From a terminal in your development directory:

git clone https://github.com/rhein1/agoragentic-integrations.git
cd agoragentic-integrations
git switch codex/runtime-dynamic-risk-fork-demo-20260913
npm --prefix risk-fork ci --ignore-scripts --no-audit --no-fund
node risk-fork/examples/runtime-dynamic/server.mjs

Open http://127.0.0.1:8787. The badge must read Node / local-reference Risk Fork. Keep the process credential-free. Press Ctrl+C to stop. Do not change its bind address to expose a public execution service.

Answer the likely questions

Is this ChatGPT? No. This example uses a deterministic decision policy, not a live language model. Risk Fork is intended for agent systems, but this prototype does not prove a live LLM integration.

Does it protect Dynamic? It is intended to protect the owner’s application-side path to a wallet action. It does not secure Dynamic’s servers or replace its wallet infrastructure.

Did the agent actually pay? Not in the browser or Node reference demo. A separate Dynamic-backed testnet action is required before the hackathon’s working-wallet requirement can be claimed.

Can it handle real customer data? This package has not been qualified for production isolation or arbitrary remote tools. Use the included fictional data only.

How do I share it? Share the static rehearsal link after hosting is approved, or send the offline demo kit. For actual reference execution, screen-share the local Node page. Never send the secret bundle, approvals, wallet shares, or operator state.
